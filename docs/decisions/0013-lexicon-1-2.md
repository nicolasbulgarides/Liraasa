# ADR-0013 — The 1.2 lexicon update, and how 1.2 is built

- **Status:** accepted
- **Date:** 2026-10-17
- **Phase:** 1.2

## Context

The author's 1.2 brief asked for new grammar (possession precedence, an
instrumental preposition, frequency correlatives, two motion metaphors), three
reglosses, predictable glosses for unused slots, about 60 new roots in three
tiers, kinship and gender words, compounds and derivations. It also asked for
a sound-collision checker to vet every new spelling, and for every change to go
through a changeset.

1.1 was a vocabulary-only supplement with its grammar frozen (ADR-0009), and
the 1.2 grammar rulings G24–G31 were recorded as a changeset on top of it
(ADR-0012). 1.2 changes grammar sections, glosses of carried entries and
closed classes, so the 1.1 integration script could not be rerun as it stood.

The author chose the design questions (gender roots, kill, grave, priest and
prophet, widowhood) and then delegated every spelling pick and the remaining
questions: "use best judgement, integrate everything". The options, checker
results and recommendations are in `review/1_2_candidates.md`. Each op's
`reason` records that the pick was delegated.

## Decision

### 1. 1.2 is built from frozen 1.1 by applying changesets

`npm run integrate:1.2` (`scripts/integrate_1_2.ts`) reads
`data/lexicon/liraasa_1_1.json`, halts unless its sha256 is `819b002c…6e18`,
applies `2026-10-17-grammar-rulings` then `2026-10-17-lexicon-1-2` through the
pure `applyChangesets` (`src/core/change/apply.ts`), audits the result and
writes `liraasa_1_2.json` plus `integration_report_1_2.json`. `--check` writes
nothing. The build is deterministic, and a test rebuilds it and compares the
result with the file on disk byte for byte.

Every op checks that it lands on what it says it replaces: an `edit_gloss`
whose `from` is not the current gloss, an `activate_slot` on a used slot, or
an `edit_example` whose text has moved all halt the build.

### 2. New op types, with payloads in the changeset

The existing ops cover roots, compounds, glosses, slots, metadata, rulings and
examples. Four kinds of change had no op, so four were added:

| Op                    | `entry`                                 | Payload                             |
| --------------------- | --------------------------------------- | ----------------------------------- |
| `add_function_word`   | its `fw_` id                            | `function_words[]` in the changeset |
| `add_correlative`     | its `cr_` id                            | `correlatives[]`                    |
| `add_derivation`      | `derivation:<base id>:-<suffix>`        | `lexicalised_derivations{}`         |
| `add_motion_metaphor` | `motion:<prefix>-:<verb's headword id>` | `motion_metaphors{}`                |

`add_root` and `add_compound` take their full entry from `headwords[]`, with
forms generated by rule, never supplied. Every entry is named by id, never
by spelling (CLAUDE.md). A `ChangeRecord` gained two optional fields:
`field`, which says what an `edit_metadata` changes, and `archive`, which moves
an old gloss into `legacy.archived_senses`.

### 3. Ids go inline in 1.2

ADR-0008 put ids inline from 1.1 on, but the 1.1 integration never wrote them.
The 1.2 build does: 1.0 entries keep their sidecar ids, the 1.1 additions are
minted in lexicon order (`lx_…_1100`–`1418`), and the 1.2 additions follow
(`lx_minva_1419` onward), so the changeset can name entries before the build
runs. The build fails if a changeset names an id other than the one it mints.

### 4. Edited carried entries say so

An entry whose gloss 1.2 changes gets `status_1_2: "REGLOSSED"`, and new
entries carry `status_1_0: "NEW"`, `status_1_2: "NEW"` and `since: "1.2"`. The
`status_1_0: "NEW"` is kept for the reason in ADR-0009 §4.

### 5. Rhyme families are rebuilt

1.1 carried 1.0's 387 families unchanged, so its 319 new headwords belonged to
none. 1.2 rebuilds them the way `build_1_0.py` did, by last four letters over
every headword: 466 families. A test checks that the rebuild reproduces 1.0's
families exactly from 1.0's headwords.

### 6. Validation

`scripts/validate_1_2.py` runs the unmodified `validate.py` and reuses
`validate_1_1.py`'s supplement for checks 5, 9 and 18, run against
`since == "1.2"`. Two checks are edition-aware:

- **Check 12** counts a gloss changed since 0.8 on a CARRIED entry as
  accounted for only if a 1.2 op records exactly that slot.
- **Check 25** asserts that 1.1 is carried verbatim except where an op
  records the change, section by section.

All 25 checks pass.

`scripts/check_sounds.py` is the sound checker the brief asked for. One rule
was tightened against the author's validator: new words must be two edits from
**reserved** spellings as well as active ones, because validate.py's check 18
counts both. Six first picks failed that rule and were replaced before
integration.

### 7. Language decisions recorded here

- **Gender:** `minva` (woman; female) and `tarnu` (man; male). Neither is the
  negative of the other. Kinship stays neutral, and gender is marked by a
  compound where one exists, otherwise by the adjective (1.2:G36). Aunt and
  uncle are phrases (`minvasan purmafamli`), because a compound would nest.
- **In-laws:** `rilde` (kinship by marriage), as the modifier of a compound.
- **Grandparents:** `purmamare` and `purmapilo`, "the parent's mother /
  father", after `purmafamli`.
- **Priest and prophet:** `luminela` (light + person) and `mernonela` (morning
  - person), because there is no future root and `futu` is a particle.
- **Widowhood:** `nemerivo` (sorrow + companion), neutral between widow and
  widower; `devorivona` is narrowed to divorce.
- **Kill and grave:** `karko` (kill) and `tomnu` (grave) are their own roots.
  `daigosan` becomes "dead; mortal", and its old sense is archived.
- **No new root where the lexicon already had the word:** confusion is
  `cerena`, pondering `pensa`, pregnancy `linufule`, ripe `hunra`, and hero
  `corviyo`. Predictable slots were activated under 0.8:R2 instead.
- **North and south:** `veludarno` (toward the stars) and `sulbadarno` (toward
  the noon sun). Midnight is `nullocemnu`.
- **`diba` may stand before a quantifier** (`diba muya lirari`, too many
  songs). The editor's parser allows this for `diba` only; whether `ruli` may do
  the same is not decided.

## Consequences

- **The 1.2 lexicon:** 1497 headwords (464 primal roots, 1033 compounds),
  10,479 forms, all distinct and all regenerated by rule. It also has 151
  function words, 39 correlatives, 29 lexicalised derivations and rulings
  1.2:G24–G36.
- **The editor, the handoff JSON and the grammar guide** now read 1.2. The
  guide has a "New words in 1.2" part with every root's seven-form table, and a
  changelog generated from the changesets.
- **Pre-existing sound-audit findings** are reported, not fixed, in
  `review/sound_audit_1_1.json`. 1.2 adds one: `solovu` (boulder, a requested
  derivation) is one edit from the root `molovu`. Derivations are outside the
  root distance rule, so it stands, and it is reported for the author.
